## High

### HI-01: Scenario built-ins shadow project FUNCTIONs named SET, GET and so on, and deadlock the process

**File:** `pkg/scenario/builtins.go:37-72`, `pkg/interp/interpreter.go:1407-1421`, `pkg/testing/runner_project.go:101-104`
**Issue:** `RegisterBuiltins` installs SET, GET, SIM_*, SIM_RAMP, RUN_CYCLES and ADVANCE_TIME in `LocalFunctions` of the plant's own interpreter. That interpreter also runs the project PROGRAMs, and `evalCall` consults `LocalFunctions` before `FuncDecls`. A project that declares `FUNCTION GET` or `FUNCTION SET`, both ordinary names, gets the scenario built-in instead of its own function inside every scan. Inside `Project.Tick` the Runtime mutex is held, so the built-in's `rt.Get`, `rt.Set` or `Clock` re-locks it. Reproduced with `stc test --project proj/ tests/`:
```
FUNCTION GET : INT  VAR_INPUT x : STRING; END_VAR  GET := 42; END_FUNCTION
PROGRAM MAIN ... y := GET('MAIN.y'); ...
=> fatal error: all goroutines are asleep - deadlock!
   (*Runtime).Get <- (*Session).get <- evalCall <- ... Project.Tick
```
With `x : INT`, the test instead fails with "GET: argument 1 must be a STRING", which points at the user's correct code. The "test bodies run outside Project.Tick" rule is enforced only for the test body, not for project code that happens to use the same names.
**Fix:** Resolve the built-ins only from the TEST_CASE body, never from project POUs:
- Register them on a separate lookup consulted only when the call's env is the test env, or give `Interpreter` a `testFunctions` map that `evalCall` checks only while `ExecStatements` runs the test body. Clear the flag in `SaveCallState` while RUN_CYCLES ticks.
- Let user `FuncDecls` win over test built-ins, and have the runner emit a diagnostic when a project POU name collides with one.
- As defence in depth, make `Session` methods return an error when called while the Runtime mutex is held, for example through a `Project.inTick` flag, so a misuse fails instead of deadlocking.
- Add a regression test with a project `FUNCTION GET`.

### HI-02: Scenario `expect` on STRING values passes when only the text after the last `.` or `#` matches

**File:** `pkg/scenario/exec.go:311-336`
**Issue:** `Equal` applies `stripEnum` to both sides of every string comparison, keeping only the text after the last `#` or `.`. This was meant for enum names such as `E_State#Run`, but `Read` returns plain STRING variables as strings too. All of the following report PASS, verified by a temporary test:
```
Equal("file.txt", "other.txt")      = true
Equal("10.0.0.1", "192.168.0.1")    = true
Equal("ERR#5", "OK#5")              = true
```
A scenario asserting a STRING value, such as a serial reply, an IP address or a status text, cannot fail on its prefix. This is a false PASS in a test tool. The comparison is also case-insensitive for real STRING values, which D-04 intends only for enum names.
**Fix:** Strip an enum prefix only when the actual value is an enum. Have `Plant.Read` mark enum values, for example by returning a small `enumName` string type or by checking `Value.Enum != ""` before `ToJSON`. Compare plain STRING values exactly. In `Equal`:
```go
case string:
    if a, ok := actual.(enumName); ok {
        return strings.EqualFold(stripEnum(x), stripEnum(string(a)))
    }
    s, ok := actual.(string)
    return ok && s == x
```
Add tests for STRING values containing `.` and `#`.

## Medium

### ME-01: `stc serve --opcua` exits 0 after the scan stopped on a runtime error

**File:** `cmd/stc/serve_cmd.go:161-185`
**Issue:** When `runProjectServe` returns an error and an OPC UA server is running, serve calls `src.Stop`, prints `scan_stopped`, and waits for SIGINT or `--duration`. It then prints the status and returns `writeProjectStatus(...)`, which is nil. The process exits 0 although the PLC program died. CI jobs and supervisors that run `stc serve --opcua ... --duration 30s` cannot detect a crashed scan. Without `--opcua`, the same error correctly exits non-zero.
The same path also treats a failing final `--persist` save as `scan_stopped`, because `runFree` joins the save error into the run error. In that case it stops OPC UA writes although the scan completed.
**Fix:** Keep `runErr` and return `fmt.Errorf("serve: %w", runErr)` after printing the status. Separate the save error from the scan error in `runFree`, for example by returning `(scanErr, saveErr)`, so only a scan error calls `src.Stop`.

### ME-02: Link and forced-input values are silently truncated to the slot width, and IEC literal parsing overflows

**File:** `pkg/scenario/plant.go:213-263` (`encodeSlot`, `encodeInt`), `:267-296` (`ParseIECInt`)
**Issue:**
- **Truncation:** `encodeInt` only range-checks 1-bit slots. A scenario `link = { path = "...^Value", value = 300 }` on an 8-bit slot, or `SIM_SET_LINK` and `stc_sim_write` on a bound USINT input, passes `Check` in Prepare. `ForceInput` then truncates it to 44. The test drives a different stimulus than written, with no diagnostic.
- **Negative values:** a negative value on an unsigned slot is accepted the same way.
- **Overflow:** `ParseIECInt` negates a `uint64` without bounds. `"-9999999999999999999"` parses as `8446744073709551617`, and `"16#FFFFFFFFFFFFFFFF"` as `-1`. Both were verified.

**Fix:** In `encodeInt`, check `n` against the slot's signed or unsigned range for `slot.BitLen < 64` using `signedSlot`, and return an error such as "value 300 does not fit an 8-bit unsigned slot". Prepare then reports it as SCN007. In `ParseIECInt`, reject `u > math.MaxInt64` for positive values and `u > 1<<63` for negative ones, unless the caller targets an unsigned 64-bit slot.

### ME-03: `stc-mcp --opcua` serves anonymous write access with none of the HI-04 controls

**File:** `cmd/stc-mcp/sim.go:124-146`, `cmd/stc-mcp/main.go:44`
**Issue:** `startOPCUA` uses `opcua.DefaultConfig()` with only `Endpoint` and `PKIDir` set. That means anonymous clients may write, there is no `--allow-anonymous-write` or `--security` flag, and there is no warning when the host is empty or not loopback. `--opcua :4840` therefore exposes every writable PLC variable to the LAN without notice. The `stc serve` fix for review 1 HI-04 was not applied here. The server also starts lazily on the first sim tool call, which the `--opcua` help text does not mention.
**Fix:** Reuse `serveConfig`-style flags in `stc-mcp`, default `--opcua` hosts to loopback, and print the same exposure warning on stderr. stdout is the MCP stream, so the warning must not go there. Document the lazy start, or start the session eagerly when `--opcua` is given.

### ME-04: `pkg/projectload.AttachECat` is dead, untested and wrong if used

**File:** `pkg/projectload/ecat.go:11-38`, `cmd/stc/project_run.go:178-179`
**Issue:**
- **Dead and untested:** after the three merges, every caller builds its network through `scenario.BuildPlantSpec` and `PlantSpec.New`. `AttachECat` and the `ECat` type have no callers and no tests, and `pkg/projectload` has 0% own-test coverage.
- **Wrong if used:** `AttachECat` attaches the network after `LoadProject`, so `RuntimeOpts.Network` is never set. The Tc2_EtherCAT mocks then have no backend, unlike `PlantSpec.New`, which sets `ps.Network` first. Anyone who picks it up as the documented shared loader gets broken `FB_EcGetSlaveState` and SDO mocks.
- **Redundant wrappers:** `countErrors` in `project_run.go` and `loadProjectSpec`/`loadProjectAnalysis` are pass-through wrappers left from the merge.

This conflicts with the project rule that nothing ships without verified branch coverage.
**Fix:** Delete `AttachECat` and `ECat`, and call `projectload.CountErrors` directly. Add a `pkg/projectload` test file covering `Load` for project, .st, directory, missing-file and mixed-argument errors, plus `ExpandSTInputs` and `RunTolerant`.

## Low

### LO-01: A Live run keeps evaluating expects after Finish when a Tick failed

**File:** `pkg/scenario/stepper.go:69-75, 111-115, 141-167`, `cmd/stc-mcp/sim.go:188-216`
**Issue:** `BeforeTick` sets `inTick`. A Tick error skips `AfterTick`, so `inTick` stays true, and `Finish(runErr)` leaves `waits` in place. `stc-mcp` lets the agent keep stepping after a Tick error. The next successful `AfterTick` passes its `!l.inTick` guard because it does not check `Done()`. It then evaluates the stale waits, appends assertions to the already-finished report and increments `k`. Later `stc_sim_step` results then carry spurious `scenario_failures`.
**Fix:** In `Finish`, set `l.inTick = false` and `l.waits = nil`. Make `AfterTick` return early when `l.Done()`.

### LO-02: `stc_sim_write` is not atomic and silently loses writes to explicit AT %I variables

**File:** `cmd/stc-mcp/sim.go:177-179, 253-279`
**Issue:**
- **Not atomic:** `Write` calls `rt.Set` first and then `plant.Apply` for bound inputs. If the force fails, the tool reports an error, but the runtime value has already changed. An enum value whose `ToJSON` string is not an IEC integer is one way to trigger this.
- **AT %I writes lost:** an explicit `AT %IX…` variable takes the `runtime_set` route, and the next scan's AT sync overwrites it. `Plant.set` rejects exactly this case for scenarios, but `Write` bypasses it.
- **Stale comment:** the `Step` comment says it "re-applies the input forces", but the code does not.

**Fix:** Route `Write` through `plant.Check` and then `plant.Apply(ActSet)` for every path. `Plant.set` already forces bound inputs and rejects AT %I variables. Read the value back only on success, and fix the comment.

### LO-03: The AT %I guard matches only whole variables

**File:** `pkg/scenario/plant.go:101-141, 134`
**Issue:** `atIn` stores `ROOT.VAR` keys and `set` compares the exact path. `SET('MAIN.aIn[1]', …)` or `GVL.stIn.bFlag` on an explicit `AT %IB` array or struct is accepted, then overwritten by the next AT sync.
**Fix:** Normalise the path and reject it when any `ROOT.VAR` prefix up to the first `.` or `[` after the variable name is in `atIn`.

### LO-04: Edge cases in conversions and SIZEOF

**File:** `pkg/interp/stdlib_convert.go:302, 323`, `pkg/interp/stdlib_sys.go:175-223`
**Issue:**
- **Unsigned to real:** `ULINT_TO_LREAL` and `LWORD_TO_REAL` of values at or above 2^63 return negative numbers, because `toFloat` uses `float64(int64)` with no unsigned case.
- **Real to integer:** `LREAL_TO_ULINT` above 2^63, and NaN or Inf to any integer, use an implementation-defined `int64(float)` conversion.
- **SIZEOF of 64-bit time types:** LTIME and LDT values report 4 bytes, because all `ValTime` and `ValDateTime` values return 4.
- **SIZEOF of strings:** a `STRING(255)` reports 81 bytes. This is documented, but `MEMCPY(..., SIZEOF(str))` then copies too little.

**Fix:**
- Convert through `uint64` when `isUnsignedBits(v.IECType)`.
- Clamp or error on out-of-range and non-finite floats.
- Use `IECType` to return 8 for LTIME and LDT.
- Carry the declared string length on string values, or look it up from the declaration in `evalSizeof`.

### LO-05: ScriptedPeer delays are one Step shorter on an EL6001

**File:** `pkg/ecat/devices/el6001.go:149-159`, `pkg/ecat/devices/serial_peer.go:13-24, 107-115`
**Issue:** `EL6001.Step` calls the peer's `Write`, `Tick` and `Read` in the same Step. A rule with `Delay: 1` is therefore released and read in the Step that sent the request, which is identical to `Delay: 0`. `Delay: N` gives N-1 Steps of latency, while `ScriptRule` documents "Ticks before the reply becomes readable".
**Fix:** Tick the peer before `transmit`, or document `Delay` as "N-1 Steps on an EL6001" and add a test that pins the Step count for `Delay: 1`.

### LO-06: The `stc test` text summary omits errored tests

**File:** `cmd/stc/test_cmd.go:226`
**Issue:** A TEST_CASE that ends with a runtime error is counted in `result.Errors` but not printed. The probe run printed `1 tests, 0 passed, 0 failed` with FAIL and exit 1. Plant mode makes errors common, through plant initialisation or RUN_CYCLES runtime errors.
**Fix:** Print `%d tests, %d passed, %d failed, %d errors`.

### LO-07: The coverage gate does not cover the v1.2 packages

**File:** `.testcoverage.yml:14-28`, `scripts/coverage-gate.sh:52`
**Issue:** The `-coverpkg` change is correct: the module path keeps `third_party/awcullen-opcua` out, and CI and the script agree. Only the v1.0 packages have per-package thresholds, though. `pkg/scenario`, `pkg/ecat`, `pkg/ecat/devices`, `pkg/opcua`, `pkg/opcua/bind` and `pkg/projectload` are held only by the 85% total, so ME-04's 0% package passes the gate.
**Fix:** Add overrides for the v1.2 packages at their current levels, for example `pkg/scenario` 95, `pkg/ecat/devices` 95 and `pkg/projectload` 90 after ME-04. Mirror them in the awk table in `coverage-gate.sh`.

### LO-08: The SaveState comment is stale, and SaveState resets file permissions

**File:** `pkg/interp/persist.go:162-166, 208-210`
**Issue:** The doc comment still says it "writes path+\".tmp\"". Since LO-02 of review 1, it uses `CreateTemp`. `writeAtomic` also always chmods to 0644, so a state file the user restricted to 0600 becomes world-readable on the next save.
**Fix:** Update the comment. `Stat` the existing file and reuse its mode, falling back to 0644.

### LO-09: Serve start-up text says "only 0.0.0.0:4840", and SIGINT during start-up skips the persist save

**File:** `cmd/stc/serve_cmd.go:154, 287-290`
**Issue:** `printServeInfo` treats only a leading `:` as all interfaces. `--opcua 0.0.0.0:4840` and `[::]:4840` print "only 0.0.0.0:4840", although the warning path, `exposed()`, knows better. Separately, `signal.NotifyContext` is installed only after the scenario and OPC UA start-up. A SIGINT during a slow certificate generation kills the process with the default handler, without the final `--persist` save. Nothing has run yet at that point, so the impact is small.
**Fix:** Use `exposed()`'s host test for the "all interfaces" text. Install the signal context at the top of `runServe`.
