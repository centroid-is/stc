# v1.2 Milestone Code Review

**Reviewed:** 2026-10-06
**Focus:** what a user hits running `stc serve <tsproj> --io ... --opcua :4840` and `stc sim --scenario` today.
**Method:** read of the serve/OPC UA/interp/ecat/twincat sources; `go vet ./pkg/... ./cmd/...` (clean); `go test -race` over `pkg/opcua/...` and `cmd/stc` serve/OPC UA tests (clean); a scratch-copy probe test for the I/O codec (CR-01, reproduced).

## Summary

Mutex discipline around `Runtime`/`Project` is sound: `Tick`, `GetMany`, `CheckSet` and `Set` all take `rt.mu`, OPC UA writes are drained on the scan goroutine, and the race detector is clean. CiA402 transition masks and status words match IEC 61800-7-201, the ADS error codes (0x7, 0x706, 0x745) are correct, and sign extension in both codecs is correct.

The serious defects are in the process-image codecs. Every array with a non-zero lower bound is shifted by one element when bound to I/O or used as an SDO buffer, because the codecs walk the interpreter's padding slots below `ArrayLow`. `ARRAY[1..n]` is the TwinCAT norm, so this silently feeds wrong I/O to PLC logic. The other high-impact issues are torn OPC UA struct writes and the `stc serve` security defaults.

Deferred items in `.planning/phases/*/deferred-items.md` and the known interpreter speed were not counted.

## Critical Issues

### CR-01: I/O codec reads and writes the padding slots of 1-based arrays

**File:** `pkg/interp/iocodec.go:41-49, 95-105, 223-233, 270-278`
**Issue:** The interpreter stores `ARRAY[lo..hi]` with direct indexing: `Array` has `hi+1` slots, and slots below `ArrayLow` are padding (`pkg/interp/value.go:74-77`, `fb_instance.go:497`). `bitSize`, `codecSupports`, `decode` and `encode` all iterate `v.Array` from index 0. The padding element is therefore mapped to the first image bits, every real element is shifted by one, and the last element falls off the slot. `ecat.Resolve` sizes the variable from the declaration (`collect.go:326-336`, 8 bits for `ARRAY[1..8] OF BOOL`), so the link is accepted. The cursor then clamps at 8 bits and `a[8]` always reads 0.

Reproduced on a scratch copy with `a : ARRAY[1..8] OF BOOL` decoded from `0x01` and `w : ARRAY[1..2] OF INT` decoded from `34 12 78 56`:
```
a: len(Array)=9 low=1 bitSize=9
a[1]..a[8] = false            (expected a[1]=true)
w bitSize=48 w[1]=0x5678 w[2]=0x0   (expected 0x1234, 0x5678)
```
This affects TcLinkTo links and explicit or wildcard AT bindings (`project_io.go` uses the same codec and `ioByteLen`). Outputs are hit too: `aOut[1]` is written to bit 1, not bit 0. Existing tests only use `ARRAY[0..5]`.
**Fix:** Iterate from `ArrayLow` everywhere the codec walks an array, and add 1-based tests for BOOL, INT and struct-element arrays on both directions:
```go
case ValArray:
    for i := v.ArrayLow; i < len(v.Array); i++ {
        n += c.bitSize(v.Array[i], elem)          // same loop shape in codecSupports/decode/encode
    }
// decode: copy cur.Array, then decode only out.Array[cur.ArrayLow:]
```

## High

### HI-01: SDO/state pointer buffers have the same padding shift

**File:** `pkg/interp/ecat_services.go:349-355` (encodeValue), `:373-377` (decodeValue)
**Issue:** `encodeValue` and `decodeValue` iterate all of `v.Array`. `FB_EcCoESdoRead` with `pDstBuf := ADR(aData)` and `aData : ARRAY[1..4] OF BYTE` stores SDO byte 0 in the padding slot. Then `aData[1]` receives byte 1, and the last byte is lost. `FB_EcCoESdoWrite` sends a leading zero byte and truncates the payload by one byte at `cbBufLen`. `FB_EcGetAllSlaveAbnormalStateChanges` and `FB_EcGetSlaveCRCError` buffers are affected the same way.
**Fix:** Walk `v.Array[v.ArrayLow:]` in both functions. Share one array-iteration helper with CR-01 so the two codecs cannot diverge again.

### HI-02: ADR() of a struct member or array element is rejected by every Tc2_EtherCAT mock

**File:** `pkg/interp/ecat_services.go:252-265` (`ptrTarget`), callers `ecat_fbs.go:166, 252, 362, 383`
**Issue:** `evalAdr` returns `Value{Kind: ValPointer, Ref: p}` for `ADR(st.member)` and `ADR(arr[i])` (`stdlib_sys.go:248-251`). `ptrTarget` only handles `PtrEnv/PtrVar` and reports "null pointer" for these. The FB then finishes with `bError=TRUE, nErrId=16#706`. `pDstBuf := ADR(stSdo.nValue)` and `ADR(aBuf[0])` are the common real-world forms, and they work on a real PLC. The mock steers users into "fixing" correct code.
**Fix:** Resolve `v.Ref` with `readRef`/`writeRef`, as `ref_path.go:196` already does for dereference:
```go
if v.Ref != nil { return readRef(v.Ref) }        // ptrTarget
...
if v.Ref != nil { return writeRef(v.Ref, out) }  // writePtrBytes instead of PtrEnv.Set
```

### HI-03: OPC UA struct writes are torn across scans and partially applied on failure

**File:** `pkg/opcua/publish.go:262-266`, `pkg/opcua/bind/runtime.go:74-90`, `:102-114`
**Issue:** A whole-struct write is decomposed into leaf writes, and each leaf is queued by a separate `src.Write` call that takes and releases `s.mu`. `ApplyPending` runs concurrently on the scan goroutine through the `BeforeTick` hook. It can drain the first k leaves before tick N and the rest before tick N+1, so the PLC executes one scan with half-old, half-new recipe or setpoint structs. If leaf k+1 fails `CheckSet` or hits `MaxPending`, leaves 1..k stay queued and are applied. The client meanwhile receives `Bad*` and believes nothing changed. A struct with more than 4096 leaves can never be written.
**Fix:** Add `RuntimeSource.WriteBatch([]leafWrite)`. It validates every leaf first, then appends all of them under one `s.mu` critical section, with the capacity check applied to the whole batch. Call it from the struct write handler.

### HI-04: `stc serve --opcua` exposes unauthenticated write access on all interfaces, with no way to restrict it

**File:** `pkg/opcua/server.go:34-46, 141-163, 224`, `cmd/stc/serve_cmd.go:62-63, 203-210`
**Issue:**
- **Binding:** awcullen listens on `":port"`, so `--opcua 127.0.0.1:4840` still binds every interface. The host only changes the advertised URL. A user who tries to restrict the server to loopback is silently not protected.
- **Writes:** anonymous is the only identity, and Write permission is granted to the Anonymous role. Any host on the LAN can change every `OPC.UA.DA`-writable PLC variable, including whatever drives EtherCAT outputs through `--io`.
- **Secure mode:** `--security basic256sha256` keeps Anonymous with write access and `WithInsecureSkipVerify`, so any self-signed client certificate is trusted. The flag name suggests access control that does not exist.

**Fix:**
- Bind the listener to the requested host by passing a pre-bound `net.Listener` or a patched awcullen option, and default to `127.0.0.1:4840`.
- Make all-interface binding an explicit `--opcua 0.0.0.0:4840`, with a startup warning when anonymous writes are enabled on a non-loopback address.
- In `basic256sha256` mode, drop `WithInsecureSkipVerify` in favour of a trusted-client PKI directory, or rename the mode to make clear it encrypts only.
- Consider a `--opcua-readonly` flag that grants Anonymous only Browse|Read.

## Medium

### ME-01: EtherCAT devices run on less time than the PLC when tasks are not harmonic

**File:** `pkg/interp/project.go:205-209`
**Issue:** `binder.preScan(p.base)` steps the network by one base tick, but only on Ticks where some task is due. With tasks of 4 ms and 6 ms, the base tick is 2 ms. Tasks are due on 7 of every 10 base ticks, so 7 × 2 ms of device time pass per 20 ms of PLC time. ATV320 ramps, EL9222 timing, state-change delays and SDO latency all run about 30% slow relative to the TON timers in the PLC code.
**Fix:** Track `lastNetStep` and pass the elapsed virtual time, `now - lastNetStep`, to `preScan`. Alternatively, step the network on every Tick and only sync the images when a task runs.

### ME-02: After the scan stops, OPC UA writes still report Good but are never applied

**File:** `cmd/stc/serve_cmd.go:137-143`, `pkg/opcua/bind/runtime.go:74-90`
**Issue:** On a runtime error, serve keeps the address space up and waits on `<-ctx.Done()`. `ApplyPending` only runs inside the dead scan loop. Every HMI write is validated, queued and answered with `Good`, the queue silently fills to 4096 entries, and later writes fail with `BadInternalError`. Operators see accepted writes with no effect.
**Fix:** Add a `RuntimeSource.Stop` or "frozen" flag, set when `runProjectServe` returns an error. Once set, `Write` returns `ErrNotWritable`, which maps to `BadNotWritable`. Alternatively, set every node's AccessLevel to read-only at that point.

### ME-03: Multi-dimensional arrays are published but every read fails

**File:** `pkg/opcua/publish.go:152-169, 273-292`, `pkg/opcua/typemap.go:124-134`, `pkg/interp/fb_instance.go:487`, `pkg/interp/runtime_path.go:81-83`
**Issue:**
- **Plain arrays:** the interpreter models only the first dimension, but OPC UA publishes `ARRAY[a..b, c..d]` with the product length. `sliceOf` then rejects the value because the lengths differ, and every read returns `BadNoData`.
- **Arrays of structs:** a struct containing a multi-dimensional array of structs builds leaf paths like `x[1,2].m`. The runtime path parser rejects these with "multi-dimensional arrays not supported", so the whole struct node reads `BadNoData`.
- **No warning:** neither case produces a diagnostic at build time.
- **Large arrays:** arrays above `maxArraySlots`, which are truncated by the interpreter, fail the same way.

**Fix:** In `opcua.Build`, skip multi-dimensional arrays and arrays of more than 10000 elements, including struct members, with a diagnostic, until the interpreter models them. Alternatively, publish such structs as Objects whose eligible members are served individually.

### ME-04: Explicit AT overlays bit-pack BOOLs and ignore alignment, unlike TwinCAT memory

**File:** `pkg/interp/iocodec.go:204-219`, `pkg/interp/project_io.go:29-80`
**Issue:** The codec gives BOOL one bit and packs struct members back-to-back, which is right for TcLinkTo to bit-packed PDO entries. Explicit `AT %IB`/`%QB`/`%MB` declarations of structs and `ARRAY OF BOOL` use the same codec. On TwinCAT, a BOOL occupies one byte, and members are aligned to their size. `stIn AT %IB0 : ST_Mix` with members `b0, b1 : BOOL; n : INT` puts `n` at byte 2 on a PLC, but at bit 2 here. Overlapping word or byte AT variables, and HMI tags using byte offsets, then see different data than on the target.
**Fix:** Give the codec a layout mode. Keep `packed` for EtherCAT links, and add `memory` for AT slots: BOOL as one byte, natural alignment capped at pack mode 8, and struct size rounded to its largest member. Use `memory` in `allocIO`/`syncIOIn`/`syncIOOut`.

## Low

### LO-01: OPC UA server and listener goroutine leak on start-up failure

**File:** `cmd/stc/serve_cmd.go:168-177`, `pkg/opcua/server.go:230-258`
**Issue:** `startOPCUA` returns without `srv.Stop()` when `Publish` or `Start` fails. `Start` leaves `ListenAndServe` running after the readiness timeout. The CLI exits, so the leak is harmless there, but the same functions are reused from `stc-mcp`, which is long-lived.
**Fix:** Call `srv.Stop()` on the `Publish` and `Start` error paths, and call `s.srv.Close()` before returning the timeout error from `Start`.

### LO-02: State file save is not fully crash-safe and races between instances

**File:** `pkg/interp/persist.go:182-190`
**Issue:** The directory is not fsynced after `os.Rename`, so a power loss can roll back to the old file on ext4 or XFS. The fixed `path+".tmp"` name means two `stc serve` processes sharing a `--persist` file overwrite each other's temporary file.
**Fix:** Use `os.CreateTemp(filepath.Dir(path), filepath.Base(path)+".*.tmp")`, and open and `Sync()` the directory after the rename on non-Windows systems.

### LO-03: plcproj item paths are case-sensitive and MSBuild-escaped names are not unescaped

**File:** `pkg/twincat/plcproj.go:85-92`
**Issue:** TwinCAT projects are authored on Windows, where `POUs\Main.TcPOU` and `POUs/MAIN.TcPOU` resolve to the same file. On Linux CI the import fails with "file not found" for case drift that TwinCAT never notices. MSBuild escapes `( ) ; ' % @ $` as `%XX` in `Include`, so `FB_Foo%28Bar%29.TcPOU` is looked up literally.
**Fix:** Unescape `%XX` sequences in `Include`. When `os.Stat` fails, fall back to a case-insensitive match per path segment and emit a warning diagnostic naming the on-disk spelling.

### LO-04: EL9222 treats Reset held high at start-up as a rising edge

**File:** `pkg/ecat/devices/el9222.go:78-81`
**Issue:** `lastReset` starts false, so a PLC that powers up with `Control__Reset=TRUE` clears a trip that was injected before the first Step, for example from a scenario. PLC code that relies on "Reset must be pulsed" is then not exercised in that case.
**Fix:** Seed `lastReset` from the first observed `Reset` value, using a `seeded bool` flag, so only a real rising edge counts.

### LO-05: Pointer-buffer struct layout is guessed from the first type with the same member names

**File:** `pkg/interp/ecat_services.go:410-425` (`memberOrder`)
**Issue:** The member order of a struct value is taken from the first registered STRUCT, alphabetically, that has the same member set. Two DUTs with the same member names in different orders, which is common for versioned DUTs, encode in the wrong order.
**Fix:** Carry the declared type name on struct Values, or use `Value.Fields`, which already holds declared order (`value.go:78-80`), instead of searching `TypeDecls`.
