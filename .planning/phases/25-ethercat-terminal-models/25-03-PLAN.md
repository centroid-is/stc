EL6001 vendor 2 product 0x17713052 (393293906, verified in baader.xml slave "Office.A1.03 (EL6001)"). The export lists several PDO alternatives (5-byte "Inputs" with Status + Data In 0..4, 22-byte with Data In 0..21, and "COM Inputs" with split Status__* bits). Phase 24 keeps only the active ones in Slave.Pdos; the model must work for whichever is active, deriving the data length from the number of "Data In n"/"Data Out n" entries.
Handshake (Beckhoff el600x_el602x_en.txt lines ~6540-6670 and CONTEXT EL6001 decision): Ctrl word bit 0 TransmitRequest (toggle), bit 1 ReceiveAccepted (toggle), bit 2 InitRequest, bit 3 SendContinuous, bits 8-15 OutputLength. Status word bit 0 TransmitAccepted (toggle), bit 1 ReceiveRequest (toggle), bit 2 InitAccepted, bit 3 BufferFull, bits 4-6 Parity/Framing/Overrun error, bits 8-15 InputLength.
Baader requests (FB_BaaderSerial.TcPOU, local only at /Users/jonb/Projects/sildarvinnsla/Baader/gagnasofnun/POUs/Serial/): 'md$R', 'mt1$R', 'ma$R', 'checkhardware$R', lone '$R' flush; reply terminator '$R$N+'. The PDO handshake lives in FB_SerialFramer.TcPOU in the same folder.
